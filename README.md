# Web BM Building (bmbuilding.sk)

Statický web firmy BM Building, s.r.o. (stavebný dozor, stavbyvedúci, stavebný manažment, Pezinok). Generátor `build.py` číta obsah z `obsah/` a šablónu zo `sablona/` a zapíše hotový web do `web/`. Bez redakčného systému, bez cookies, bez cudzích zdrojov. Jediný vlastný skript `sablona/app.js` (filter realizácií, lightbox galérie, slider úvodu, jemné objavenie sekcií úvodu, spodná lišta, pretočenie kót); web ukáže všetok obsah aj bez neho.

Vzhľad: štýl Čiara podľa našej ukážky Ateliér Olovnica (`products/arling-sk/web/ukazky/architekti/`), ktorý si klient vybral. Prevzaté sú kostra, mriežka 4, 8 a 12 stĺpcov s vlasovými čiarami, rytmus, písmo Geist a Geist Mono, kóty, mierka, olovnica nad ı v mene, tlačidlá a jeden pohyb pri vstupe (pri `prefers-reduced-motion` hneď konečný stav). Jeho sú logo (`sablona/logo.svg`), modrá #17476f z loga namiesto bronzu (len prízvuk a tmavá sekcia Realizácie), fotky a údaje stavieb. Rozbor: `ops/weby-na-mieru/klienti/bmbuilding/dizajn-olovnica/OLOVNICA-ROZBOR.md`, stav: `dizajn-olovnica/STAV.md`. Šírka obsahu: do 1920 px okna najviac 1760 px; od 1921 px (široké monitory, Andrej 25. 11. 2026 pri 2560 px: „hluché miesto vpravo“) rastie s oknom s okrajom 80 px až po 2400 px (okno 2560 px), mriežka, vlasové čiary, hlavička aj sekcie ostávajú na jednej mriežke (`--sirka`), H1 úvodu rastie s ňou (64 px pri 1920, 96 px pri 2560 px, najviac 7 % výšky okna), titulná fotka detailu ide cez celých 7 stĺpcov, karta Činnosti bez zoznamov tečie v dvoch stĺpcoch, vizitka Kontaktu má 4 stĺpce, výrez tabuľky V médiách 3 stĺpce s textom po pravý okraj a stránka služby s dlhým zoznamom má zoznam v dvoch stĺpcoch so spoločnými riadkami (trieda `riadky-N` z `doslovny_text(..., riadky=True)`, do 1920 px jeden stĺpec) a box s dokladom na 4 stĺpce. ## Spustenie
Potrebuje Python 3 a Pillow (`pip install pillow`). Žiadna sieť. Testy navyše potrebujú NumPy (porovnanie orezov fotiek v galérii) a Node.js v PATH: `nastroje/zoznam_spravanie.cjs` spustí časť 5 `sablona/app.js` (filter, zoradenie, Zobraziť ďalšie) nad malým falošným DOM bez balíkov a test porovná výsledok s očakávaním (linka bmb-fb-uplnost, oprava 2). Časť 5 berie z `app.js` výstupu zostavy (zhusteného bez komentárov), značky sú riadky kódu `var filtre = ...` a `var dlg = ...`.

```
python build.py               # ostrý beh pre https://bmbuilding.sk/
python build.py --nahlad      # náhľad (napr. https://<účet>.github.io/bmbuilding/)
python build.py --vystup DIR  # iný výstupný priečinok (predvolený web/)
python build.py --obsah DIR   # iný priečinok obsahu (predvolený obsah/)
python build.py --fotky-web DIR  # hotové webové verzie fotiek (predvolený fotky-web/)
python build.py --hosting apache --vystup D:/ARLing-media/klienti/bmbuilding/web-ftp  # ostrý web pre FTP na WebHouse, len z čistého pracovného stromu na commite schváleného náhľadu (SPUSTENIE-FTP.md časť 1.1)
python -B -X utf8 -m pytest -q test_build.py   # testy (asi 3 až 4 min; ide aj python -m unittest -v test_build)
```

- **Ostrý beh:** sitemap.xml s lastmod, robots.txt so Sitemap, CNAME (bmbuilding.sk), .nojekyll (pri `--hosting apache` namiesto nich `.htaccess`, nižšie), žiadne noindex. robots.txt menuje výslovne GPTBot, ClaudeBot, PerplexityBot, Google-Extended a Bingbot v jednej skupine s `Allow: /` pred skupinou pre všetkých (firemný checklist `ops/runbook.md`, RFC 9309 časť 2.1; `build.py` `AI_ROBOTI`). `llms.txt` (formát https://llmstxt.org/) skladá `llms_txt()` len z `obsah/firma.json`, `texty.json`, realizácií a osvedčení: meno firmy, description úvodu, O firme, kontaktné a fakturačné údaje, osvedčenia SKSI, odkazy na služby, realizácie (druh, rola, projektant alebo autor, roky) a Oprávnenia, Kontakt, Ochranu údajov; údaje z obsahu so escapovaním markdownu (audit naplno 25. 11. 2026, položka 7).
- **GitHub Actions:** pri `GITHUB_ACTIONS=true` ide ostrý beh len s premennou prostredia `BMB_OSTRY=ano`, inak build sám prepne na náhľad (náhľad na github.io nesmie ísť do indexu). Krok „Zostaviť web“ v `obsah.yml` už má `env: BMB_OSTRY: ${{ vars.BMB_OSTRY }}`; pri GitHub Pages stačí po nastavení domény premenná repozitára `BMB_OSTRY=ano`, pri ceste FTP na WebHouse ju nenastavovať (GitHub Pages ostane náhľad s noindex, ostrý web na doménu ide z `build.py --hosting apache` cez FTP; audit naplno 25. 11. 2026, položka 49). Chýbajúca realizácia alebo fotka z `uvod_slider` je v Actions chyba zostavy (kód 1, časť Šablóna).
- **Náhľad:** na každej stránke `<meta name="robots" content="noindex, nofollow">`, robots.txt `Disallow: /`, bez sitemap, llms.txt, CNAME a .nojekyll; 404.html má cesty absolútne od `/bmbuilding/` bez `<base>`, aby „Preskočiť na obsah“ ostalo na 404 (`sablona/nastavenia.json`, zaklad_nahladu). og:image a twitter:image idú v náhľade z `adresa_nahladu` (https://arling.sk/bmbuilding/), aby odkaz na náhľad vo WhatsAppe mal obrázok; canonical a og:url ostávajú na bmbuilding.sk (položka 12).
- **FTP na WebHouse (`--hosting apache` alebo premenná `BMB_HOSTING=apache`; audit naplno 25. 11. 2026, položka 1):** len ostrý beh, s `--nahlad` alebo v GitHub Actions bez `BMB_OSTRY=ano` kód 2. Výstup musí byť mimo repozitára a prázdny alebo len so súbormi predchádzajúcej FTP zostavy (na FTP sa nahrá celý priečinok), zoznam zostavy je vedľa neho (`<priečinok>.zostava.json`), nie v ňom (`manifest_ftp`). Namiesto CNAME, .nojekyll a stránok v `index.php/` (priečinok by sa na hostingu zrazil so súborom index.php Joomly) zapíše `.htaccess` (`build.py` `htaccess`): pravidlá prepisu len pre bmbuilding.sk a www.bmbuilding.sk, `/.well-known/` bez presmerovania (Let's Encrypt), 32 starých adries Joomly zo `sablona/presmerovania.json` jedným skokom 301 rovno na https a holú doménu (query preč, kotva `#cinnost` bez kódovania), ostatné adresy pod index.php na úvod, priečinok bez lomky na adresu s lomkou, www a http na https (podmienka na `%{HTTPS}` podľa návodu WebHouse), 404 s vlastnou stránkou pre každé meno v koreni, ktoré zostava nezapísala (súbory a priečinky Joomly, staré zálohy), pre priečinok bez index.html aj pre PHP; `DirectoryIndex index.html index.php`, `ErrorDocument 404 /404.html`, typy AVIF, WebP, woff2 a webmanifest, UTF-8, hlavičky nosniff, Referrer-Policy, X-Frame-Options, `frame-ancestors 'self'`, Permissions-Policy a COOP, cache podľa typu (`CACHE_APACHE`: HTML 0, app.js rok, písma a fotky mesiac) a gzip (`GZIP_APACHE`); HSTS zámerne nie (pre návštevníkov na rok nevratné). Časť Hosting na `/ochrana-udajov/` uvádza WebHouse, s. r. o. ako sprostredkovateľa podľa jeho verejných podmienok (`texty.json` `ochrana.webhouse`, bez platných údajov zostava zlyhá); pri GitHub Pages ostáva GitHub. Pravidlo „priečinok bez lomky“ platí len pre mená zostavy, priečinok Joomly s prázdnym index.html (`/images`) dostane hneď 404. Zoznam zostavy má pole `commit` (commit, z ktorého sa stavalo, `commit_repozitara` číta len `.git/HEAD` a referencie, git nespúšťa) a výpis ho ukáže riadkom `commit:`; pred zostavou musí byť pracovný strom čistý a HEAD rovnaký ako origin/main a commit schváleného náhľadu (postup, časť 1.1), inak by na doménu išli necommitnuté alebo neschválené zmeny. Pravidlá bez Apache overí `python nastroje/htaccess_simulacia.py --web DIR` (simulácia podmnožiny Apache 2.4 nad každým súborom a starou adresou, podpožiadavka DirectoryIndex bez pravidiel s príznakom R ako mod_rewrite.c, kód 1 pri chybe), po nahratí `python nastroje/kontrola_spustenia.py --web DIR` (len GET a HEAD na bmbuilding.sk); na sucho `python nastroje/htaccess_simulacia.py --web DIR --server` vypíše port a kontrola ide s `--lokalne PORT`. Či hosting dovolí direktívy .htaccess, overí pred prepnutím priečinok `python nastroje/htaccess_skuska.py --web DIR --vystup .../skuska-htaccess` (tie isté direktívy bez pravidiel prepisu, nahrá sa vedľa Joomly a potom zmaže). Postup zálohy, nahratia a návratu: `ops/weby-na-mieru/klienti/bmbuilding/kolo-1/SPUSTENIE-FTP.md`; test `TestHostingApache`.
- Interné odkazy sú relatívne, ten istý výstup funguje na doméne aj v podpriečinku github.io. Absolútne (https://bmbuilding.sk) sú len canonical, og:url, og:image (v ostrom behu), JSON-LD, sitemap a llms.txt.
- Beh je deterministický: rovnaký vstup dá rovnaké bajty, v súboroch nie je čas behu. lastmod realizácie je najnovší z `datum`, `upravene` a `vydanie` (`sablona/nastavenia.json`, deň poslednej zmeny šablóny), ostatných stránok `vydanie`, úvodu, služieb a zoznamu realizácií najnovší z toho všetkého. Rok v päte je z toho istého najnovšieho dátumu. Neplatný kalendárny dátum (2026-13-45) sa vynechá s varovaním.

- `nastroje/predlohy_web.py` (len PC, potrebuje numpy a scipy, spúšťať pod zámkom PC): hotové webové verzie fotiek do `fotky-web/`. Berie predlohy z `D:/ARLing-media/klienti/bmbuilding/web-predlohy/predlohy.json`, inak zdroj z `obsah/`. Pre každú fotku a formát hľadá najmenšiu kvalitu, pri ktorej MS-SSIM jasu drží prah 0,995, pri titulných fotkách (hrdina, fotka karty realizácie a novinky, ilustračné fotky, Postup a O firme) 0,997. Pri predlohe z AI (Upscayl) robí šírky do 1,25 x šírky zdroja (titulné fotky do 1,6 x) Lanczosom zo zdroja, AI predlohu len nad ňou. Výrez karty z rámika (`karta_foto` `vyrez`) zapíše pri súbore `vyrez`, build ho bez zhodného záznamu nevezme. Súbory, ktoré web naozaj použije, zistí z plánu `build.Web`. Je idempotentný, má `--limit-min` a `--procesy` a `--vycisti` zmaže nepoužité súbory aj nepoužité varianty záznamu. Kalibrácia: `ops/weby-na-mieru/klienti/bmbuilding/presnost/oprava-fotky.md`.
