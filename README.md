# Web BM Building (bmbuilding.sk)

Statický web firmy BM Building, s.r.o. (stavebný dozor, stavbyvedúci, stavebný manažment, Pezinok). Generátor `build.py` číta obsah z `obsah/` a šablónu zo `sablona/` a zapíše hotový web do `web/`. Bez redakčného systému, bez cookies, bez cudzích zdrojov. Jediný vlastný skript `sablona/app.js` (filter realizácií, lightbox galérie, slider úvodu, jemné objavenie sekcií úvodu, spodná lišta, pretočenie kót); web ukáže všetok obsah aj bez neho.

Vzhľad: štýl Čiara podľa našej ukážky Ateliér Olovnica (`products/arling-sk/web/ukazky/architekti/`), ktorý si klient vybral. Prevzaté sú kostra, mriežka 4, 8 a 12 stĺpcov s vlasovými čiarami, rytmus, písmo Geist a Geist Mono, kóty, mierka, olovnica nad ı v mene, tlačidlá a jeden pohyb pri vstupe (pri `prefers-reduced-motion` hneď konečný stav). Jeho sú logo (`sablona/logo.svg`), modrá #17476f z loga namiesto bronzu (len prízvuk a tmavá sekcia Realizácie), fotky a údaje stavieb. Rozbor: `ops/weby-na-mieru/klienti/bmbuilding/dizajn-olovnica/OLOVNICA-ROZBOR.md`, stav: `dizajn-olovnica/STAV.md`.

Stránky: úvod (1. kolo pripomienok, `ops/weby-na-mieru/klienti/bmbuilding/kolo-1/ZMENY-KOLO-1.md` 3A, rozpis `kolo-1/uvod/UVOD.md` a `kolo-1/uvod/UVOD-V3.md`: hrdina na prvú obrazovku so sliderom stavieb vľavo a vpravo nadtitulkom, H1 „BM Building, s.r.o. je stavebno-manažérska spoločnosť so sídlom v Pezinku.“, dvoma odsekmi O firme (`texty.json` `uvod.o_firme_hrdina`, bez 20 rokov), údajmi s ikonami, zdrojom z ORSR a tlačidlami Zavolať a Napísať e-mail; hrdina je celý na prvej obrazovke aj na notebookoch: pri okne do 960 px výšky ide blok O firme pod hrdinu ako jeden celok (vlasová čiara, vľavo nadtitulok O firme, vpravo oba odseky, delenie 4 a 8 ako list Činnosti, začína 48 px pod fotkou, teda pod okrajom prvej obrazovky), H1 najviac 6 % výšky okna, do 820 px hustejšie údaje (`kolo-1/oprava-1/OPRAVA.md`, `kolo-1/oprava-2/OPRAVA.md`, meranie 1280 x 720 až 1920 x 1080); vo vysokom okne sú odseky vpravo pod H1 a nadtitulok O firme je len pre čítačku; na mobile a tablete H1 bielym písmom na fotke s tmavým prechodom len v spodnej časti (horná polovica čistá, kontrast H1 nad všetkými 11 fotkami aspoň 4,8 : 1), bez riadku kľúčových slov na fotke, štítok stavby pod počítadlom (nie na fotke), hneď pod fotkou údaje a tlačidlá, potom blok O firme s nadtitulkom (oprava-2); hneď pod ním Činnosť, celý doslovný text starého webu z `sablona/texty.json` `cinnost_doslova` v troch kartách ako technický list (3A.7, rozpis `kolo-1/cinnost/CINNOST.md`: na počítači vľavo pripnutá hlava s ikonou, číslom 01 až 03, nadpisom, počtom realizácií služby z rolí s odkazom, osvedčením SKSI s odkazom na Oprávnenia a odkazom na stránku služby, vpravo celý text, dlhé zoznamy v dvoch stĺpcoch so značkou bodov ako na stránkach služieb (bez čísel 01, 02, oprava-1); pod kartami veta o osvedčeniach SKSI a „Čo hovorí stavebný zákon“ s dvomi rozbaľovacími otázkami, prvá otvorená); Kontakt ako modrý blok s ikonami Facebook, LinkedIn a Instagram. ## Spustenie
Potrebuje Python 3 a Pillow (`pip install pillow`). Žiadna sieť. Testy navyše potrebujú NumPy (porovnanie orezov fotiek v galérii) a Node.js v PATH: `nastroje/zoznam_spravanie.cjs` spustí časť 5 `sablona/app.js` (filter, zoradenie, Zobraziť ďalšie) nad malým falošným DOM bez balíkov a test porovná výsledok s očakávaním (linka bmb-fb-uplnost, oprava 2).

```
python build.py               # ostrý beh pre https://bmbuilding.sk/
python build.py --nahlad      # náhľad (napr. https://<účet>.github.io/bmbuilding/)
python build.py --vystup DIR  # iný výstupný priečinok (predvolený web/)
python build.py --obsah DIR   # iný priečinok obsahu (predvolený obsah/)
python build.py --fotky-web DIR  # hotové webové verzie fotiek (predvolený fotky-web/)
python -B -X utf8 -m pytest -q test_build.py   # testy (asi 3 až 4 min; ide aj python -m unittest -v test_build)
```

- **Ostrý beh:** sitemap.xml s lastmod, robots.txt so Sitemap, CNAME (bmbuilding.sk), .nojekyll, žiadne noindex.
- **GitHub Actions:** pri `GITHUB_ACTIONS=true` ide ostrý beh len s premennou prostredia `BMB_OSTRY=ano`, inak build sám prepne na náhľad (náhľad na github.io nesmie ísť do indexu). Po prepnutí domény bmbuilding.sk treba v kroku „Zostaviť web“ workflowu pridať `env: BMB_OSTRY: ${{ vars.BMB_OSTRY }}` a premennú repozitára `BMB_OSTRY=ano` (krok pre linku bmb-obsah alebo Fable). Chýbajúca realizácia alebo fotka z `uvod_slider` je v Actions chyba zostavy (kód 1, časť Šablóna).
- **Náhľad:** na každej stránke `<meta name="robots" content="noindex, nofollow">`, robots.txt `Disallow: /`, bez sitemap, CNAME a .nojekyll; 404.html má cesty absolútne od `/bmbuilding/` bez `<base>`, aby „Preskočiť na obsah“ ostalo na 404 (`sablona/nastavenia.json`, zaklad_nahladu).
- Interné odkazy sú relatívne, ten istý výstup funguje na doméne aj v podpriečinku github.io. Absolútne (https://bmbuilding.sk) sú len canonical, og:url, og:image, JSON-LD a sitemap.
- Beh je deterministický: rovnaký vstup dá rovnaké bajty, v súboroch nie je čas behu. lastmod realizácie je najnovší z `datum`, `upravene` a `vydanie` (`sablona/nastavenia.json`, deň poslednej zmeny šablóny), ostatných stránok `vydanie`, úvodu, služieb a zoznamu realizácií najnovší z toho všetkého. Rok v päte je z toho istého najnovšieho dátumu. Neplatný kalendárny dátum (2026-13-45) sa vynechá s varovaním.
- Pred zápisom zmaže len súbory, ktoré zapísal predchádzajúci beh (zoznam `web/.zostava.json`), a to až keď sú všetky nové obrázky vyrobené; ak niektorý zlyhá, výstup ostane celý a build skončí kódom 1. Obrázky s rovnakým odtlačkom vstupu sa znova nekódujú (kódovanie beží vo vláknach), súbory s rovnakými bajtmi sa neprepisujú.
- **Fotky (linka bmb-fotky):**
  - Každá fotka je `<picture>`: zdroj `type="image/avif"` so `srcset` a `sizes` a `<img>` so zálohou WebP.
  - AVIF má šírky 480, 720, 960, 1440, 1920 a 2400 do šírky predlohy. WebP ide najviac do 1440 px. Štandardná šírka sa vynechá, keď je predloha od nej širšia menej ako o 10 %.
  - Odložené fotky slidera úvodu majú AVIF v `data-avif` a `app.js` ho dá do `picture` až pri načítaní. Lightbox berie AVIF z `data-avif` alebo `data-sirky-avif`. Odkaz galérie s náhľadom so `srcset` (nie malá fotka) nemá `data-srcset` ani `data-avif`, lebo by boli bajtovo rovnaké ako `srcset` náhľadu; `app.js` (`nahladZ`) ich vtedy vezme z `img` a zo zdroja AVIF náhľadu v odkaze.
  - Reprezentatívna fotka z nastavenia `karta_foto` je v galérii prvá (1. kolo pripomienok 5.3); fotka karty, ktorú nahradila (`karta_nahradena`), ostáva v galérii ako bežná fotka, nikdy prvá veľká.
  - Predloha je hotová webová verzia z `fotky-web/` (`manifest.json` podľa sha256 zdrojovej fotky z `obsah/`, súbory sa len skopírujú). Keď sha256 nesedí, napríklad pri novej fotke zo systému obsahu, build fotku zakóduje sám z `obsah/` s kvalitou `KVALITA` (AVIF 60, WebP 80, prepíše ich `nastavenia.json` `kvalita_fotiek`). Bez kodeku AVIF ide len WebP s varovaním.
  - Vždy sa robí sRGB (ImageCms), otočenie podľa EXIF a výstup je bez metadát.
  - Malá fotka v galérii, osvedčenia a OG obrázky ostávajú bez AVIF.
  - Postup a kalibrácia: `ops/weby-na-mieru/klienti/bmbuilding/fotky-kvalita/KODOVANIE.md`, AVIF v GitHub Actions: `fotky-kvalita/ci-avif.md`.
- Výstup sa overí: bez pomlčiek em a en a bez výkričníkov, inak build zlyhá (kód 1). Texty z obsahu sa pred tým upravia: pomlčka medzi rokmi dá „až“, výkričník bodku.

## Čo vznikne
`/`, `/stavebny-dozor/`, `/stavbyveduci/`, `/stavebny-manazment/`, `/realizacie/`, `/realizacie/<slug>/` pre každú zverejnenú realizáciu, `/opravnenia/`, `/kontakt/`, `/ochrana-udajov/`, `404.html`, presmerovania starých adries Joomla (`/index.php/...`, statické stránky s meta refresh, canonical a odkazom; zoznam `sablona/presmerovania.json`), `obrazky/<slug>/<nn>-<šírka>[-45|-54].<avif|webp>` (šírky podľa predlohy, nikdy väčšie než predloha, bez metadát), `og/<slug>.jpg` a `og/bmbuilding.jpg` (1200 x 630), `fonts/`, `app.js`, `logo.svg` (kópia `sablona/logo.svg`, hlavička a päta cez `<img>`), `favicon.svg` (kópia `sablona/logo-favicon.svg`), `favicon.ico`, `favicon-32.png`, `favicon-48.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` a `site.webmanifest` (kópie zo `sablona/favicon/`), `logo.png` (512 x 512 z `sablona/logo.svg`, JSON-LD `Organization.logo` aj `image`).

Bezpečnosť: CSP v meta značke (`default-src 'none'`, štýl a JSON-LD cez sha256 hash, ktorý build spočíta), každý údaj z JSON escapovaný podľa kontextu, JSON-LD s escapovaným `<`, `>` a `&`, slugy len `[a-z0-9-]`, cesty k fotkám len vnútri `obsah/obrazky`, odkaz na Facebook len https na facebook.com.

## Štruktúra obsahu (dohoda s linkou bmb-obsah, nemeniť)
- `obsah/realizacie/<slug>.json`: `id`, `slug`, `nazov`, `miesto`, `rola`, `projektant`, `roky`, `text`, `fotky` (zoznam `{"subor": "obsah/obrazky/<slug>/01.jpg", "alt": "..."}`), `zdroj` (`web`, `fb`, `sprava`), `fb_url`, `datum` (RRRR-MM-DD), `poradie`, `zverejnene`. Voliteľné `investor`, `zhotovitel`.
  - Voliteľné aj `upravene` (RRRR-MM-DD, posledná zmena, ide do lastmod a dateModified) a `titulok` (vlastný title do 60 znakov, ak sa názov nezmestí; dlhší build nepoužije a vypíše varovanie. Bez neho build skúsi názov s mestom, prvú a poslednú časť názvu, potom začiatok názvu po prvú čiarku; názov nikdy neseká uprostred vety a keď sa nič nezmestí, dá celý názov, Google ho skráti sám).
  - Chýbajúce alebo prázdne polia nespôsobia pád: riadok sa nevypíše. Realizácia bez fotiek nejde do mriežky kariet, ale do kompaktného zoznamu „Ďalšie realizácie“ pod ňou (miesto, rola, roky stavby), a dostane OG obrázok bez fotky. Fotka, ktorá sa nedá celá dekódovať (useknutý súbor), sa vynechá s varovaním.
  - `zverejnene: false` sa nezobrazí. Zlý alebo duplicitný slug, chýbajúci názov a pokazený JSON sa preskočia s varovaním. Chýbajúca fotka sa vynechá s varovaním.
  - Poradie: `poradie` vzostupne, potom `datum` zostupne, potom `slug`. Zoznam realizácií ide od najnovších podľa rokov stavby (`zorad_chronologicky`); karta bez vhodnej fotky má rám s vlasovými uhlopriečkami (nikdy rozmazaná, malá ani zväčšená fotka, fotka pôvodného stavu nie je obal).
  - Úvod neukazuje pás realizácií (od ÚVOD v3, ZMENY-KOLO-1.md 3A.6), všetky stavby sú v zozname `/realizacie/`. V GitHub Actions (`GITHUB_ACTIONS=true`) je chýbajúca realizácia alebo fotka slidera (`uvod_slider`) chyba zostavy (kód 1): build nič nezapíše, krok nasadenia sa nespustí a na webe ostane posledná dobrá verzia (fb-ostro A4, test `TestChybaVActions`); lokálne len varovanie.
  - Zoznam `/realizacie/` pri desiatkach realizácií (linka bmb-fb-uplnost): všetky karty sú v HTML a bez JS viditeľné (odkaz na každú realizáciu pre vyhľadávače), `app.js` ukáže prvých `realizacie_naraz` (12) z výberu a tlačidlo „Zobraziť ďalšie (N)“; filter (druh, roky, miesto) a zoradenie (popisky „najnovšie“, „najstaršie“, „abecedne“, aby sa zmestili pri 390 px) idú cez všetky karty, počet v `aria-live`, fokus po Zobraziť ďalšie na prvú novú kartu. Karty zoznamu majú statickú kótu bez pretáčania číslic (kratšie HTML). Nad `realizacie_na_stranu` (300) stránky po desaťročiach. Test `TestSestdesiatRealizacii` stavia web z kópie obsahu rozmnoženej na 60; to isté pre meranie robí `ops/weby-na-mieru/klienti/bmbuilding/fb/nastroje/rozmnoz_obsah.py`.
  - V jednej realizácii nie je dvakrát ten istý záber (fotka starého webu a tá istá z Facebooku): zlučuje ich `ops/weby-na-mieru/klienti/bmbuilding/fb/nastroje/zapis_obsah.py`, test `test_galeria_bez_zhodnych_fotiek` (dHash 144 bitov do 6).
  - Fotky JPEG, PNG alebo WebP; nad 2000 px sa najprv zmenšia na 2000.
- `obsah/firma.json`: `meno`, `konatel`, `adresa` (`ulica`, `psc`, `mesto`), `ico`, `ic_dph`, `zapis_or` (do päty len ak `zapis_or_overit` nie je true), `den_zapisu`, `telefon`, `telefon_href`, `email`, `facebook`, `posobnost`, `sluzby` (slug, názov, krátky popis a činnosti doslovne zo starého webu; krátky popis je jedna doslovná veta, stavebný manažment nemá na starom webe zoznam činností), `opravnenia`, `hodiny` (nepoužité, nie sú vo faktoch).

## Obsah z Facebooku a zo správy (`.github/obsah/stiahni.py`, workflow Obsah)
- Sťahovač verzie 2 (doplňovanie, `ops/weby-na-mieru/klienti/bmbuilding/fb-ostro/NAVRH.md` časť 3.3) mení len položky, ktorých id je z Facebooku (`fb-<číslice>`) alebo zo správy obsahu (id nezačína `web-`, `s-` ani `fb-`). Realizácie a novinky z prvého naplnenia (v D1 id `web-…`, v repozitári id rovné slugu, novinky bez id) sú len v repozitári a menia sa tu, aj keď ich API vracia. Ich úprava v správe obsahu sa na web nedostane.
- Spravovaná položka: `obsah/realizacie/<slug>.json` alebo `obsah/novinky/<slug>.json` (`id`, `slug`, `datum`, `nadpis`, `text`, `fotky`, `zdroj`, `zverejnene`), fotky `obsah/obrazky/<slug>/NN.jpg` alebo `obsah/obrazky/novinky/<slug>/NN.jpg`. Mení sa v správe obsahu; úpravu v repozitári Action prepíše a zachová len kľúče, ktoré API nepozná (`titulok`, `kategoria`, `rok_prispevku`, pri novinke `realizacia` a `fb_url`).
- Mazanie len podľa zoznamu `stiahnute` z API (v správe zmazané alebo Len koncept), len položky v `obsah/.obsah-stav.json` (verzia 2) a len súbor s tým istým `id`. Položka, ktorá v API chýba, ostane; starý worker bez `stiahnute` nemaže nič.
- Kolízia (nová položka z D1 má slug súboru alebo priečinka fotiek inej položky): beh skončí kódom 1, nič nezapíše a beh Action je červený. Riešenie: iný názov v správe obsahu alebo premenovanie v repozitári.
- Brzda mazania (fb-ostro A3, pre každú verziu sťahovača): krok „Uložiť zmenu obsahu do main“ skončí chybou bez commitu a pushu, keď zmena odoberá z `obsah/` viac ako 20 súborov (`git diff --cached --no-renames --name-only --diff-filter=D -- obsah`, prvých 50 v logu behu). Úloha nasadenie sa nespustí a web ostane posledný dobrý. Jedna položka zmaže najviac 1 JSON a 16 fotiek (`max_fotiek`). Keď je väčšie mazanie v poriadku (klient naraz stiahol viac položiek), Fable spustí ten istý sťahovač na PC v `products/bmbuilding` (`python -B -X utf8 .github/obsah/stiahni.py --api https://arling-obsah.arling.workers.dev/api/bmbuilding --obsah obsah`, najprv so `--sucho`), skontroluje zmazané súbory, commitne a pushne; ďalší beh Action už nič nemaže. Test `TestBrzdaMazania` v `.github/obsah/test_workflow.py` spustí skript kroku v bash s falošným git (skutočný git sa nespúšťa); bez bash sa tieto skúšky preskočia a ostane kontrola textu kroku.
